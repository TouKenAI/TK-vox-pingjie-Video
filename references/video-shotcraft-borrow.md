# video-shotcraft → V300 融合手册(10 张高价值卡翻译)

来源:Vincentwei1021/video-shotcraft(7,012★/Remotion/TypeScript)。本文件是把 158 张配方卡中
可翻译到我们 Pillow 系统的**动效意图+参数表**沉淀为 kf() 关键帧格式。
仓库本地缓存:`打包暂存/video-shotcraft/`(96MB,含全部 158 卡源码)。

## 使用方式
每张卡 = 1 条量化规则 + kf() 参数模板。scene JSON 直接套用,不需要 Remotion。

---

## 1. ease-out-back 丝滑落定(来源: list-reveal / card-stack)
**发现**: 丝滑感 = 落位时轻微过冲后扣住,不是匀速到达。过冲量 ~1.002-1.05,肉眼几乎看不见但体感明显。
**翻译**: 渲染器已加 `ease-out-back` 缓动(过冲峰值 1.05)。
**用法**: 文字卡入场 ease 从 `"ease-out"` 改为 `"ease-out-back"`,或用 `"ease-spring"`(更温和)。
**适用**: 所有文字卡入场;主体道具落定;阶梯攀登落点。

## 2. opacity 渐进(来源: list-reveal)
**发现**: 透明度在入场行程 45% 时就应吃满(`min(1, p*2.2)`),避免半透明项和背景糊在一起。
**翻译**: card() 生成器已把入场 opacity=1 提前到 `f_in - round(8 * 0.45)` ≈ `f_in - 3`,而非 `f_in`。
**适用**: 所有文字卡;半透明入场的道具。

## 3. stagger 递减(来源: R2 + card-stack)
**发现**: 等距错帧读作机械;首卡 8 帧、逐卡 ×0.7、最低 2 帧,产生"越来越快"的加速感。
**翻译**: `stagger_decreasing(base=8, decay=0.7, n=5)` → [8, 6, 4, 3]。
**用法**:
```python
gaps = stagger_decreasing(8, 0.7, 5)
f = f_start
for gap in [0] + gaps:
    f += gap
    L.append(card(f"t_item{i}", w, x, y, f, mode="slide"))
```

## 4. 容器漂移(来源: list-reveal 两层解耦)
**发现**: 逐项入场+容器慢速漂移是**两层独立运动**。容器漂移 ≈0.3px/f(32px/3.6s),刚好在"画面活着"和"看得出在动"之间。**这是不够丝滑的根因:我们的场景里图层各自动但容器不动。**
**翻译**: scene JSON 加 `"container_drift": {"x": [16, -16], "y": [0, 0]}`。渲染器已支持。
**用法**: 文字卡多/入场密集的场景(≥8 卡),加 32-48px 全程漂移。
**参数**: >60px 漂移会与逐项位移混淆;<10px 感知不到。

## 5. masking-tape-slap 胶带拍定(来源: paper-craft-moves A)
**发现**: 卡片悬浮微晃(±1.5°/±5px)被两条胶带"啪啪"按死——第二条拍下同帧晃动归零+投影变薄+整卡下沉 2px。"按死"是一帧完成的三件套。
**翻译**: 入场后挂 8-12 帧微晃(rotation ±1.5°, y ±5px),然后一帧内 rotation→0 + shadow blur 34→8 + y+2。
**适用**: 单卡定妆入场(金句卡/CTA 卡);文案重音对齐帧。

## 6. card-stack 聚拢+扇开(来源: card-stack)
**发现**: 先聚成"一摞"(数量感)再摊成"一组"(多样性),顺序关键。两层运动分离:入场(spring 逐张)与扇开(全体共享一条进度)。
**翻译**: 多卡先以 spring 逐张弹入同一位置(stagger 4f),全员落位后一次性展开为扇形(每张 +8°/+34px 递增)。
**适用**: "我们有 N 个方法"的建立镜头;多方案对比。

## 7. speed-ramp-freeze 变速定格(来源: speed-ramp-freeze)
**发现**: 匀速流读作 PPT;变速在一条运动里制造"冲刺→凝视→冲刺"。定格段配马克笔圈注。
**翻译**: 后处理帧号 remap(源动画匀速,输出帧非线性)。定格段斜率=0,解冻段斜率>1。全片 ≤2 次。
**适用**: 密集动效流中的重点暂停;数据冲击帧。

## 8. circle-iris 圆形揭示(来源: circle-match-iris)
**发现**: 新画面从圆形孔洞中扩出,圆心对准画面主角——比线性 wipe 更聚焦。
**翻译**: 新增转场模式 `circle-iris`:PIL 画圆形 mask(半径从 0→对角线),圆心=主体中心。
**适用**: 需要聚焦转场时;从特写拉全景的反向。

## 9. 呼吸预算(来源: R1)
**规则**: 关键信息落定后静止 ≥1s 再切;呼吸给品牌/关键信息,不给普通元素。
**翻译**: preflight 已加检查:最后文字卡落定帧距场景末 ≥30f。WARN 不 block。

## 10. 冲击预算(来源: R4)
**规则**: 全画面级节拍冲击(整画面 scale 泵/震屏/闪帧)全片 ≤3 处;其余拍点只动元素层。
**翻译**: preflight 已加检查:全片 radial-burst(ray_count≥12) ≤3 处。WARN 不 block。

## 不翻译清单( Remotion 独有,我们不做)
- 3D perspective transforms (rotateX/preserve-3d) — Pillow 无 3D
- SVG path morphing — 需矢量系统
- DOM 排版/实时文字渲染 — 我们用 PIL 离线
- React component composition — 技术栈不同
- Remotion 的 Chrome 渲染管线 — 保持纯 Pillow

## 审美规则补遗(R/Q 体系,跨技术栈通用)
以下规则直接补充我们的 playbook,无论用什么技术栈都适用:
- **R1**: 关键信息落定后呼吸 ≥1s——呼吸给品牌/关键信息,不给普通元素
- **R2**: 速度感来自加速度;匀速运动读作廉价 PPT;群体入场用"越来越快"+物理隐喻
- **R3**: 宁慢勿快:主体动作弧 ≥3s;初版几乎总是偏快,排时间线留 hold/rest 帧预算
- **R4**: 全画面级节拍冲击全片 ≤3 处;其余拍点只动元素层;节拍泵连打单次 ≤4 拍
- **Q4**: 光效宁缺毋滥:不群发,主角一次,裁进圆角边界
- **Q5**: 开场只给一个主角+完整动作弧(起承落),多元素并舞撑不起第一印象
- **Q8**: 结尾做成"发布会合影":全片元素四方飞入围住字标,能量推到全片峰值
- **Q9**: 飞入动画终点必须是页面布局真实槽位,不悬浮
